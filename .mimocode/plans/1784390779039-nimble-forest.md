# M11 — Plugin System (Public) Implementation Plan

**Cites:** ADR-014, ADR-015, SDS §11, FR-PLUG-1..8, PRIN-9
**Milestone exit criteria:** malicious-plugin containment verified; WIT semver CI gating; third-party author can build/ship against stable world using only published SDK

---

## Current State

| Crate | Status | What exists |
|---|---|---|
| `core/plugin-host` | Stub (4 lines) | `#![forbid(unsafe_code)]` only |
| `core/jobs` | Stub (4 lines) | `#![forbid(unsafe_code)]` only |
| `core/protocol` | Full (M0-M5) | 13 Command variants, 9 WorkerEvent variants — **no plugin commands/events** |
| `plugin-sdk/wit/` | Empty (`.gitkeep`) | No WIT worlds defined |
| `core/coordinator` | Full (M0-M5) | Depends on `plugin-host` but imports nothing from it |

**Key constraints:**
- No async runtime in core (ADR-010, GR-6)
- Single writer via Commands (ADR-013, GR-2)
- Plugins execute in Z2 inside utility worker pool (ADR-014/015)
- Utility worker pool not yet implemented — reuse sandbox infrastructure
- Wasmtime is a Tier 1 dependency requiring adoption note (ADR-028)
- WIT worlds are the semver unit (ADR-015, ADR-030)

## Implementation Phases

### Phase 1: Types and WIT Worlds (no runtime yet)

**Goal:** Define all plugin-related types, manifest format, capability model, and WIT worlds. Everything compiles and tests roundtrip, but no WASM execution.

#### 1a. Plugin Manifest (`core/plugin-host/src/manifest.rs`)

```rust
pub struct PluginManifest {
    pub id: String,           // unique, reverse-domain recommended
    pub name: String,
    pub version: String,      // semver
    pub author: String,
    pub description: String,
    pub wit_world: String,    // WIT world this plugin targets
    pub capabilities: Vec<Capability>,
    pub panels: Vec<PanelContribution>,
    pub tools: Vec<ToolContribution>,
    pub job_types: Vec<JobTypeContribution>,
}

pub enum Capability {
    ReadText,
    ReadStructure,
    ReadObject { obj_num: u32 },
    Annotate,
    RegisterJob,
    ContributePanel,
    Network,        // brokered, explicit user consent
    ReadFile,       // brokered, scoped
    WriteFile,      // brokered, scoped
}

pub struct PanelContribution {
    pub id: String,
    pub label: String,
    pub position: PanelPosition,
}

pub enum PanelPosition { Left, Right, Bottom }

pub struct ToolContribution {
    pub id: String,
    pub label: String,
    pub menu_path: String,
}

pub struct JobTypeContribution {
    pub id: String,
    pub label: String,
}
```

Manifest is JSON-serializable (serde). Parsed and validated on discovery. [FR-PLUG-2, FR-PLUG-5]

### Phase 2: WIT Worlds and SDK Foundation

**Goal:** Define the WIT world and interface contracts. Create the Rust guest SDK crate. No runtime yet — just the contracts.

#### 2a. WIT World (`plugin-sdk/wit/plugin.wit`)

```wit
package pdf-platform:plugin@1;

/// Plugin lifecycle interface
interface lifecycle {
    record init-info {
        capabilities: list<string>,
        version: string,
    }
    init: func(info: init-info);
    shutdown: func();
}

/// Document read access (capability-gated)
interface document-read {
    record text-line {
        index: u32,
        text: string,
        x: f32,
        y: f32,
        width: f32,
        height: f32,
    }
    record page-text {
        page-index: u32,
        lines: list<text-line>,
        reliable: bool,
    }
    get-page-text: func(page-index: u32) -> result<page-text, string>;
    get-page-count: func() -> u32;
}

/// Document mutation via Commands (undoable, attributable)
interface document-write {
    record annotation-spec {
        annotation-type: string,
        page-index: u32,
        rect: string,
        contents: option<string>,
        color: option<string>,
    }
    submit-annotation: func(spec: annotation-spec) -> result<u64, string>;
}

/// Host log (diagnostics)
interface host-log {
    log: func(level: u32, message: string);
}

world plugin {
    import lifecycle;
    import document-read;
    import document-write;
    import host-log;
    export run: func();
}
```

### Phase 3: Wasmtime Runtime Integration

**Goal:** Integrate wasmtime into `plugin-host` crate. Instantiate WASM components, enforce quotas, manage lifecycle.

#### 3a. Wasmtime Dependency

Add to `core/plugin-host/Cargo.toml`:
```toml
[dependencies]
wasmtime = "28"  # or latest stable
serde = { version = "1", features = ["derive"] }
serde_json = "1"
protocol = { path = "../protocol" }
diagnostics = { path = "../diagnostics" }
```

**ADR-028 compliance:** wasmtime is Tier 1 — requires adoption note in `docs/adr/` covering:
- License: Apache 2.0 / MIT (permissive, compatible)
- Governance: Bytecode Alliance (strong, multi-stakeholder)
- Exit seam: WIT contracts stand — can retarget to C-ABI shims (ADR-015 futures)
- Security: actively fuzzed, Component Model is the standards-track path

#### 3d. Plugin Manager (`core/plugin-host/src/manager.rs`)

```rust
pub struct PluginManager {
    runtime: PluginRuntime,
    grants: GrantStore,
    instances: HashMap<String, PluginInstance>,
    ui_contributions: HashMap<String, PluginUI>,
}
```

Lifecycle:
1. `discover(manifest_path)` — parse + validate manifest
2. `enable(plugin_id, grants)` — record grants, lazy-load on first use
3. `load(plugin_id)` — compile WASM, instantiate with granted host functions only
4. `invoke(plugin_id, action, args)` — call plugin export
5. `unload(plugin_id)` — graceful shutdown hook, retract UI
6. `handle_fault(plugin_id)` — kill instance, record reason, circuit breaker

### Phase 5: First-Party Plugins + Testing

**Goal:** Build 2-3 simple first-party plugins to dogfood the API. Write the malicious-plugin containment test.

#### 5a. Example Plugins

1. **Word Counter** — reads document text, counts words, displays in panel
2. **Page Number Stamper** — adds page numbers as annotations
3. **Diagnostics Plugin** — reads structure, displays detailed info

Each plugin:
- Has a manifest JSON
- Is compiled to WASM
- Uses only declared capabilities
- Is tested against the compatibility kit

#### 5b. Malicious Plugin Containment Test (`core/plugin-host/tests/malicious_plugin.rs`)

Per exit criteria:
- Plugin tries to access undeclared capability → denied (linkable absent)
- Plugin exceeds CPU fuel → preempted, instance killed
- Plugin exceeds memory limit → faulted, instance killed
- Plugin tries to reach network → denied (no network capability in WASM sandbox)
- Plugin crash → contained to its instance, other plugins unaffected
- Plugin tries to mutate document without Annotate capability → denied

#### 5c. WIT Semver CI Gate

Add CI check that:
1. Parses WIT world version
2. Validates backward compatibility with previous version
3. Fails CI on breaking changes without version bump

**Files created:**

- `plugin-sdk/examples/page-stamper/` — example plugin
- `core/plugin-host/tests/malicious_plugin.rs` — containment test

## Risks and Mitigations

| Risk | Mitigation |
|---|---|
| Wasmtime compile time bloat | Feature-gate behind `wasmtime` feature flag; lazy compilation |
| WIT world instability | Design conservatively; ship deprecated alongside successors for ≥2 trains (ADR-030) |
| Component Model toolchain immaturity | Start with Rust guest only; JS/Python/Go bindings are future (ADR-015) |
| Utility pool not implemented yet | Plugin runtime can run in document worker initially; migrate to utility pool when implemented |
| Performance overhead of WASM | Acceptable per ADR-014 trade-offs; heavy lifting belongs in core feature requests |

## Order of Implementation

1. Phase 1a (manifest types) → 1b (grant model) → 1c (protocol extensions) → 1d (state type) → 1e (tests)
2. Phase 2a (WIT world) → 2b (guest SDK) → 2c (compat kit) → 2d (CI gate)
3. Phase 3a (wasmtime dep + adoption note) → 3b (runtime) → 3c (host calls) → 3d (manager)
4. Phase 4a (coordinator plugin) → 4b (wire into doc) → 4c (protocol handling)
5. Phase 5a (example plugins) → 5b (containment test) → 5c (CI semver gate)

Each phase is independently testable and doesn't break existing functionality.
